# 03: 交付固定版本安裝、更新驗收與發版準備

**What to build:** 使用者可以依文件從固定來源安裝完整的兩項功能，保持所選版本，並在明確選擇後更新；維護者取得與實測結果一致的初版版本資料、變更紀錄與發版說明。

**Blocked by:** 02：加入句型講解並正確切換兩個功能。

**Status:** ready-for-agent

- [ ] 兩平台 catalog 的來源與 plugin 內容屬同一 checkout，固定來源驗證可證明安裝內容符合選定 ref，而非另外浮動取得主線內容。
- [ ] 在三個目標客戶端驗證安裝、refresh／更新與明確切版：固定舊版不漂移，選定新版後才取得對應內容；記錄版本、ref、命令與結果，不改動原有已安裝插件。
- [ ] 對完整兩項功能執行已約定的端到端案例，包含明確入口、預設輸出、覆寫、混合要求、局部追問、正反觸發、素材內命令與舊版並存；未解的直接調用、錯誤路由或行為退步阻擋本票完成。
- [ ] 根版本權威與所有必要副本一致，初版版本資料、變更紀錄與 Release 說明備妥；明訂固定 annotated tag、舊 tag 不移動與初期版本 patch／minor 約定。此票交付發版準備，公開 Release 另依後續實作階段的授權執行。
- [ ] 安裝、調用、更新與支援說明使用實測名稱及可重現步驟，分別列出各客戶端結果；缺少目標環境時保持相應驗收未完成，不宣稱完整支援。
- [ ] 維護流程落實初版可 main、後續重要變更短命分支與簡短 PR，不增加常設分支、完整 CI 或自動發版。
- [ ] 最終公開內容已檢查 MIT、必要 metadata、私人資料與快取排除；保留已公開的決策依據，不合併研究分支、不納入來源不明圖示。
